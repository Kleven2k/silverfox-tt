## How it works

Silverfox is a small, reprogrammable CPU for bit-banging hardware protocols, inspired by the RP2040's PIO state machines. Rather than fixed-function UART/SPI/I2C peripheral blocks, the chip contains a single general-purpose instruction set core with seven opcodes (`SET`, `WAIT`, `IN`, `OUT`, `JMP`, `MOV`, `HALT`) designed around reading pins, writing pins, counting cycles, and branching on pin state.

A protocol is implemented entirely as a *program* — a fixed sequence of these instructions loaded into the core's instruction memory at synthesis time — rather than as dedicated hardware. The same core can therefore run a UART transmit routine, and could equally run SPI, I2C, or another protocol entirely, without any change to the underlying circuit.

The design is built with [Hardcaml](https://github.com/janestreet/hardcaml) (OCaml), which generates the Verilog RTL in this repository's `src/project.v`. Full architecture and instruction set details are documented in [docs/architecture.md](architecture.md) and [docs/isa.md](isa.md).

The current design runs a UART transmit (TX) program: an 8-N-1 frame (1 start bit, 8 data bits LSB-first, 1 stop bit) is sent out on the TX pin, with bit timing generated by a busy-wait delay loop calibrated to the design's 25 MHz clock and a 115200 baud rate.

## How to test

The design's clock should be driven at 25 MHz to match the UART timing baked into the current program. On reset (`rst_n` low, then released) and with `ena` high, the design will repeatedly transmit a fixed test byte (`0x55`) on the `uo_out[0]` (TX) pin as a standard 8-N-1 UART frame: start bit low, 8 data bits LSB-first, stop bit high, each held for 217 clock cycles (one bit period at 25 MHz / 115200 baud).

Observe `uo_out[0]` with a logic analyzer or oscilloscope, or decode it with a UART receiver set to 115200 baud, 8 data bits, no parity, 1 stop bit — the decoded byte should read `0x55` (binary `01010101`), repeating.

This behavior is also verified automatically: `hardcaml/test/uart_test.ml` checks the same framing directly against the Hardcaml source, and `test/test.py` (run via `make -B` in the `test/` directory) verifies it against this repository's actual generated Verilog using cocotb and Icarus Verilog.

## External hardware

None required for the current UART TX test — a logic analyzer, oscilloscope, or UART receiver is useful but optional for observing the output.
